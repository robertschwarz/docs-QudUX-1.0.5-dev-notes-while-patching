## Findings: fixes that were marked FIXED but were wrong

These compiled but would have misbehaved at runtime.

### #03 PickSeveral: pickup popup could never be confirmed
The baseline passed all 21 args positionally, using `0` for `Amount`, `MaxWidth` and `IconPosition`. In the decompiled `PickSeveral`, the accept check is `Amount >= 0 && list.Count > Amount`. With `Amount = 0`, any non-empty selection is rejected. `MaxWidth = 0` collapses the popup width (the default is 60). `IconPosition = 0` breaks the icon padding (the default is -1).
```csharp
var results = Popup.PickSeveral(
    Title: "Which item do you want to get ?",
    Options: options,
    Icons: icons,
    AllowEscape: true
);
```

### #09 Inventory guard: QudUX hijacked the modern inventory
The baseline dropped the guard entirely, so QudUX would replace the inventory even when the modern UI was active. In the decompiled 1.0.5 `XRL.UI.Screens.Show(GO)`:
```csharp
if (Options.ModernUI && Options.ModernCharacterSheet) { StatusScreensScreen.show(...); return; }  // modern
... ScreenList[CurrentScreen].Show(GO) ...                                                         // classic InventoryScreen
```
The agent restored the guard as `!GameOptions.ModernCharacterSheet`. That version would still turn QudUX off for the **ModernCharacterSheet=on, ModernUI=off** combination, where the classic screen is still shown. The orchestrator tightened it to match the game's condition exactly:
```csharp
&& !(GameOptions.ModernUI && GameOptions.ModernCharacterSheet)
```
The Harmony target `InventoryScreen.Show(GameObject) : ScreenReturn` is unchanged, so the patch still binds.

### #10 ShowYesNo: popup sound silently muted
The baseline passed `Sound: null`. The declared default is `"Sounds/UI/ui_notification"`. Passing null doesn't crash, because `PlayUISound` guards against empty values, but it mutes the popup.
```csharp
Popup.ShowYesNo(msg, AllowEscape: false, defaultResult: DialogResult.Cancel);
```

### #02 Render: incomplete render pipeline
`ComponentRender` alone skips the `FinalRender` pass. The game's own `GameObject.RenderForUI()` and the per-object loop in `Cell` both call `ComponentRender` and then `FinalRender`. `OverlayRender` only runs on the stacked-cell path, so TileMaker doesn't need it. The fix doesn't call `RenderForUI()` directly because that would overwrite TileMaker's Examiner "unknown tile" override.

## Findings: previously broken

### #11 Brain.FactionMembership
`Brain.Factions` is write-only. In 1.0.5, `Brain.Allegiance` (`XRL.World.AI.AllegianceSet : StringMap<int>`) replaces `FactionMembership`: `SetFactionMembership` writes `Allegiance[Faction] = Feeling`. The agent checked `FactionFeelings` and ruled it out, because it holds opinions of other factions, not membership. `Keys` is an explicit interface member, which is why the code casts.
```csharp
foreach (string key in ((IDictionary<string, int>)legendaryCreature.Brain.Allegiance).Keys)
```

## Findings: confirmed OK, with notes

- **#08 `GetAwaiter().GetResult()`**: the agent checked for a deadlock and ruled it out. The shipped storage backend (`LaundryBear.PlatformServices.None.Storage`) does its I/O synchronously and calls back inline, so the task finishes before the main thread blocks. The game does the same thing itself: the `Scores.Scoreboard` getter calls `task.Wait()`. *Residual risk:* a future platform build with truly async storage would bring the deadlock risk back. The game's own code has the same exposure.
- **#05**: `Restocker` no longer exists anywhere in 1.0.5, and every vendor in `Creatures.xml` uses `GenericInventoryRestocker`. So the restock-timer dialog still shows for every vendor after the branch removal.
- **#06 / #12**: there is only one `AskString` overload. `ReturnNullForEscape` defaults to false, so Escape returns `""`, the same as before 1.0.5. `FilterString` can't become null.
- **#07**: `RemoveEffect(Effect)` returns false when passed null, and `HasEffect(string)` still matches on the class name. `RemoveEffect<T>()` and `RemoveEffect(Type)` also remove only the first match, so the current call behaves the same.
- **#04**: `CookingGameState.GetIngredientQuantity` is static with an identical signature and doesn't depend on any instance state.
